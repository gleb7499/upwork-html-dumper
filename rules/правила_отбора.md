> Дата: 2026-09-19 (обновлено под frontend-стек)
> Ниши: см. [список_ниш.md](список_ниш.md). Этот файл — только правила.
> Значения в таблицах вынесены так, чтобы их можно было менять одной правкой.

## Все правила

| Правило | Значение | Где применяется |
| --- | --- | --- |
| Оплата клиента | верифицирована | Фильтр |
| Proposals у заказа | 0–14 | Фильтр |
| Ставка (hourly) | от $15 | Фильтр |
| Бюджет (fixed) | от $50 | Фильтр |
| Уровень фрилансера | tier 1–2 | Фильтр |
| Сортировка выдачи | от новых к старым | Фильтр |
| Возраст заказов | только свежая выдача | Фильтр |
| История клиента (отзывы, траты) | без истории — ок | Ручной просмотр |
| Рейтинг клиента | не ниже 4.5 (если рейтинг есть) | Ручной просмотр |
| Жалобы в отзывах клиента | минимальное количество | Ручной просмотр |
| Открытые заказы у клиента | ≤ ~ 10 открытых + hire rate ≥ ~ 60% → ок; > ~ 10 открытых или hire rate < ~ 40% → пас. Явно нет только, которые кричат об этом. В остальном случае выдавать в итоговой выборке с советами человеку | Ручной просмотр |
| Бесплатные тесты | запрещены | Ручной просмотр |
| Объём-ловушка | дёшево ≠ мелко; считать часы. Не исключать из выборки, все равно предлагать с оговорками и конкретными потенциальными подводными камнями - окончательное решение за человеком | Ручной просмотр |
| Явный фуллтайм | пас | Ручной просмотр |
| Язык и гео заказа | Язык - английский норм, остальные - нет. Гео любой страны - сразу нет | Ручной просмотр |
| Senior-опыт / узкий домен без моего опыта | пас (для ниши 5 Next.js — брать junior/mid-задачи, senior SSR-архитектуру без опыта — пас) | Ручной просмотр |
| Чистый дизайн без кода (UI/UX, «design only») | пас — это заказы для дизайнеров, не для разработчика | Ручной просмотр |
| Мобильная разработка (React Native / Flutter / native iOS/Android), просочившаяся мимо NOT-фильтров | пас | Ручной просмотр |
| Дедлайн короче 7 дней при объёме более 30 ч | показывать в выборке, но с оговоркой +дни до контракта | Ручной просмотр |
| Пограничные / неясные случаи (в которых нужно читать описание из страницы деталей заказа) случаи | показывать всегда; скрывать только при явном НЕТ по правилам — решение за человеком | Решение при отклике |
| Оценка времени | оптимистичный / реалистичный / пессимистичный| Решение при отклике |
| Ставка при биде | бюджет как есть, не торгуемся; hourly — середина (может ближе к низу) вилки клиента. Предлагаем скидку 10-25% -  в зависимости от открытх + hire rate | Решение при отклике |

## Что можно вбивать в URL поиска Upwork

Параметры, поддерживаемые поиском `/nx/search/jobs/`:

| Параметр | Что делает | Пример значения |
| --- | --- | --- |
| `q` | Поисковый запрос (логика: AND/OR/NOT, кавычки, скобки) | `(React OR Next) NOT ("react native")` |
| `sort` | Сортировка | `recency`, `relevance` |
| `page` | Страница выдачи | `1` |
| `per_page` | Записей на страницу | `50` |
| `payment_verified` | Только верифицированная оплата | `1` |
| `proposals` | Диапазон числа откликов (можно список через запятую) | `0-4,5-9,10-14` |
| `hourly_rate` | Вилка ставки (для hourly-заказов) | `15-`, `15-50` |
| `amount` | Бюджет fixed-заказов | `50-`, `50-500` |
| `contractor_tier` | Уровень фрилансера | `1,2` |
| `category2_uid` | Подкатегория | `531770282580668418` (Web/Mobile/Software) |
| `t` | Тип оплаты: `0` — hourly, `1` — fixed; `0,1` = оба типа (фактически без ограничения) | `0,1` |
| `duration_v3` | Длительность контракта | `quarter`, `semester` |
| `workload` | Загрузка | `full_time`, `part_time` |
| `client_hires` | Число наймов клиента | `1-5`, `10-` |
| `job_status` | Статус заказа | `open` |

Синтаксис `q`: термин — обязательное слово; `OR` — альтернатива; `NOT (...)` — исключение; `"..."` — точная фраза; скобки группируют условия.

## Как правила связаны с нишами

- Позиционирование: **продаём вёрстку сайтов**, стек (React, TS, HTML5, CSS, JS) — инструмент и аргумент ставки, а не входное условие. Ведущий блок — вёрстка (ниши 1–4), React-ниши (5–9) — усиление и подъём чека. Блок D (Spring Boot, ниши 12–13) — фоном, в порядке приоритета: сначала fullstack-связка React+Spring Boot (козырь — фронт и бек одним исполнителем), потом отдельные backend/REST API заказы. Java/Spring bugfix-ниша исключена — даёт слишком много мусора.
- Блок D имеет **свои NOT-группы**: frontend-слова там не исключаются, отсекаются чужие backend-стеки (`php, python, django, ruby, rails, laravel, .NET`). JavaScript там не исключаем — токенизация цепляет Java↔JavaScript, и fullstack-заказы помечены обоими.
- Каждая ниша из `список_ниш.md` получает URL с набором фильтров из секции «Все правила» (уровень «Фильтр») и свой поисковый запрос в `q`.
- Исключения чужого стека обязательны: `php, laravel, python, django, ruby, rails` — чужой код; `wordpress, shopify, webflow, wix, squarespace, elementor, bubble, softr, carrd, framer, showit, readymag, gohighlevel, opencart` — низкобюджетные конструкторы/платформы; `"react native", flutter` — мобильная разработка, не профиль; `tester, testing, QA` — QA-заказы, просачивающиеся через dev-запросы; `designer, "UI/UX", logo, branding` — дизайн-заказы; `video, UGC, unity, "3d"` — медиа/геймдев-шум; `solana, solidity, "smart contract"` — senior-крипта. DeFi/Web3-фронтенд сознательно НЕ исключён — решение по домену за человеком. Исключение из исключений: ниша 4 (Bitrix24/CMS) — там интеграция в движок и есть предмет заказа.
- В нишах 1–3 слово `mobile` НЕ исключаем (адаптив/`mobile-friendly` — предмет вёрстки); отсекаем только `flutter OR "react native"`.
- Слово `java` НЕ исключаем (токенизация Upwork цепляет `JavaScript`) — детали в [синтаксис_запросов.md](синтаксис_запросов.md).
- Конструкторы (`wordpress, webflow, wix, squarespace, elementor`) исключены в нишах сайтов/вёрстки: там преимущественно дешёвые заказы с «своим админом». Если в выборке регулярно всплывают дорогие заказы на тему/плагин — можно обсудить отдельную пассивную нишу.
- Правила уровня «Ручной просмотр» применяются к любой выдаче любой ниши.
