# upwork-parse-diff (фаза 0)

Офлайн-утилита (Windows, Java 21+, jsoup; **без Spring, БД и сети**): читает папку с
HTML-дампами поисковой выдачи Upwork и обновляет **дашборд** — `new.md` и `rejected.md`
в родительской папке дампов. Дашборд показывает актуальное состояние текущей выборки,
а не «только новые»: повторный прогон той же папки даёт тот же файл.

## Установка (один раз)

1. Собрать/обновить дистрибутив: `bash upwork-parse-dist/build.sh`
   (офлайн-сборка: компиляция maven'ом из локального кэша, jsoup мёржится в fat jar).
2. Папку `upwork-parse-dist` добавить в PATH Windows.
3. Проверка: `upwork-parse-diff --selftest` → `STRUCTURE OK`.

## Использование

```
upwork-parse-diff                              ; из папки «Страницы» — берёт самый свежий дамп сам
upwork-parse-diff C:\Users\kseni\Documents\Фриланс\Страницы\2026-08-14_11-50
upwork-parse-diff "<папка>" [--ttl-days 90] [--db C:\path\seen.bin]
java -jar upwork-parse-diff.jar "<папка>"     ; без bat-обёртки
```

- Папка не указана → в текущей директории ищется самая свежая подпапка с именем
  вида `yyyy-MM-dd_HH-mm` (так расширение называет дампы) — берётся последняя по дате-времени.

- Папка обходится рекурсивно; имя каждого `*.html` (без расширения) пишется в поле `query`.
- `new.md` — **рабочая выборка** в родительской папке дампов: подходящие заказы,
  по которым ещё не принято решение. Неразмеченные строки переносятся между
  прогонами и дополняются свежими из новых дампов. Колонка `причина` (после
  `mark`) — свободная заметка пользователя, сохраняется между прогонами.
- **Пометки**: в любую ячейку строки поставь `❌` (не интересно) или `✅` (откликнулся).
  При следующем прогоне помеченные уходят в `history.md` и **больше никогда не
  появляются** в `new.md`, даже если заказ снова попадётся в дампах.
- `history.md` — вся разрешенная вручную работа: ❌/✅ + причина + дата.
  Парсер понимает и старый формат без колонки `причина` — старые файлы
  перечитываются без потерь.
- `rejected.md` — автоотсев текущего прогона: заказы, отсеянные жёстким
  автофильтром (❌ проставляет парсер автоматически, показывать их не нужно).
- `.upwork-pending.tsv` — скрытый машинный снапшот открытых (сортировка,
  перенос пометок). Вручную не трогать.
- `seen.bin` по-прежнему пишется (учёт «новых»/«повторных» для сводки в консоли).

## Автофильтр (жёсткие правила)

Применяется ко всем тайлам прогона. Отсеянные попадают в `rejected.md` (❌ ставит
парсер) и в `new.md` не попадают. Пустые поля (кроме оплаты) заказ не отсеивают —
он остаётся в `new.md` на ручную проверку.

1. Оплата НЕ подтверждена (`<li data-test="payment-verified">` отсутствует в тайле) — отсев.
2. Предложений: верхняя граница диапазона (`"0-4"`, `"5-10"`) > 14 — отсев.
3. Почасовой (`hourly`): нижняя граница вилки `budget` < 15 — отсев.
4. Фикс (`fixed`): сумма `budget` < 50 — отсев.
5. Рейтинг клиента < 4.5 — отсев (рейтинг «0 out of 5» = «No feedback yet» считается пустым).

Причин несколько — пишутся через запятую в колонке `reason`. Отсеянных нет —
в `rejected.md` пишется заглушка «нет отсеянных».
- `seen.bin` — **глобальный**, в `%USERPROFILE%\.upwork-parse-diff\seen.bin`
  (переопределяется через `--db`). Формат: `UWSEEN1` + count + записи UTF uid / long lastSeen.
  Атомарная запись (tmp + rename), прунинг по TTL, повреждённый файл → `.corrupt`, старт с нуля.

## Диагностика (громкая поломка вместо тихого «0 новых»)

- Разметка привязана в **одном** классе: `UpworkSelectors.java` (версия `MARKUP_VERSION`
  печатается в шапке сводки). Починка под новую разметку трогает только его.
- Файлы есть, а тайлов 0 → `STRUCTURE BROKEN`, exit code **3**, `new.md` — заглушка
  «ПРОГОН НЕВАЛИДЕН», `seen.bin` не изменяется.
- `--selftest` — прогон по встроенным фикстурам (EN- и RU-разметка) без обращения к
  файлам пользователя: `STRUCTURE OK` / `STRUCTURE BROKEN`. Проверяет и парсинг тайлов,
  и маркер `payment-verified`, и правила автофильтра на синтетических тайлах.
- Exit codes: 0 — ок; 1 — неверные аргументы/папка; 2 — ошибка записи; 3 — поломка разметки.

## Известные особенности разметки (учтены в парсере)

- Локаль выдачи бывает EN и RU: «Почасовая оплата: $ 15,00 - $ 30,00»,
  «Фиксированная цена», «Предложений: от 5 до 10», «Опубликовано вчера».
- Два формата тайлов: proposals отдельным `<li>` (старый) или инлайн рядом с датой (новый).
- uid берётся из `href` тайла (`~02…`), а не из data-атрибутов — ссылка в `new.md` всегда
  реальная, а не сгенерированная.
- `<li data-test="payment-verified">` есть только у верифицированных клиентов:
  маркер отсутствует = «оплата не подтверждена» (автофильтр отсеивает такие заказы).
