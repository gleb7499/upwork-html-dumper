# ParserUpwork — устройство проекта

Пайплайн поиска заказов на Upwork: расширение собирает страницы поиска → скрипт парсит дампы и отсеивает неподходящее → остаток фрилансер просматривает вручную.

## Структура

- `rules/` — **единый источник правды** по нишам, запросам и отбору. Меняется часто. НИЧЕГО оттуда сюда не дублировать — всегда читать файлы из `rules/` (`правила_отбора.md`, `синтаксис_запросов.md`, `список_ниш.md`).
- `extention-firefox/` — браузерное расширение (Firefox MV3, "Upwork HTML Dumper"). `urls.json` — список URL поисковых выдач, генерируется из `rules/`. `background.js`/`content.js` — скачивание страниц, `upwork-dumper.user.js` — userscript-вариант, `popup.*` — UI. Chrome-вариант удалён (2026-09-26): поддержка только Firefox. Постоянная установка: собрать `upwork-html-dumper.xpi` (zip манифеста и кода), положить как `<id>.xpi` в `extensions/` профиля Firefox Developer Edition (там отключена проверка подписи через `xpinstall.signatures.required=false` в `user.js`); обычный Firefox принимает только подписанные дополнения.
- Локальный прокси авторизации (машина пользователя, вне репо): `%USERPROFILE%\.upwork-local-proxy\proxy.js` — Node-скрипт, слушает `127.0.0.1:8899` и подставляет логин/пароль IPRoyal при пересылке на `84.55.15.1:12323`. Автозапуск — задача планировщика `UpworkLocalAuthProxy` (при входе в Windows, скрыто). Профиль Dev Edition направлен на `127.0.0.1:8899` (`user.js`), поэтому Firefox не спрашивает логин/пароль прокси. Kill-switch: `network.proxy.failover_direct=false` — при падении прокси прямого выхода в сеть нет. ⚠️ Файлы `key4.db`/`logins.json` профиля не переносить между профилями — cookie/логины зашифрованы per-profile ключом, подмена ключа тихо ломает отправку cookie (Upwork отдаёт visitor-страницы с «0 jobs found»).
- `upwork-parse-diff/` — Java 21 + Maven (jsoup) офлайн-парсер дампов. См. его `README.md`.
- `upwork-parse-dist/` — сборка и запуск парсера: `build.sh` (офлайн-сборка fat-jar), `upwork-parse-diff.jar`, `upwork-parse-diff.bat`.

## Ключевые связи

- `extention-firefox/urls.json` должен соответствовать `rules/`: фильтры из «Все правила» (`правила_отбора.md`) + запросы `q` из `список_ниш.md` (строгий и широкий на нишу). Кодировка `q`: пробел → `%20`, кавычка → `%22`, скобки → `%28`/`%29`.
- Парсер читает папку с `*.html` дампами и ведёт дашборд в родительской папке: `new.md` (открытые, ждут ❌/✅ + причину от пользователя), `history.md` (разрешённые вручную с причиной), `rejected.md` (автоотсев). Дедуп-учёт — `seen.bin` (для сводки).
- Правила отбора делятся на два уровня: «Фильтр» (попадают в URL и/или автофильтр парсера) и «Ручной просмотр» (применяет человек к выдаче). При изменении `rules/` проверять, не надо ли перегенерировать `urls.json` и не затронут ли автофильтр парсера.

## Что менять при правках

- Правила/ниши/запросы → только `rules/`, затем по необходимости перегенерировать `urls.json`.
- Разметка Upwork → только `upwork-parse-diff/src/main/java/com/example/upworkdiff/UpworkSelectors.java` (вся привязка к разметке там, есть `MARKUP_VERSION` и `--selftest` на фикстурах).
- После изменений парсера: `bash upwork-parse-dist/build.sh` и `--selftest`.
- После изменений парсера — обязательный прогон на реальных данных: свежая папка дампов в `C:\Users\kseni\Documents\Фриланс\Страницы\`, результат проверять по `new.md` / `history.md` / `rejected.md`.
- После любых проверочных прогонов на реальных данных возвращать дашборд в состояние до проверки: восстановить пометки и причины в `new.md`, удалить из `history.md` строки, появившиеся из-за проверки. Проверка не должна оставлять следов в рабочих файлах пользователя.
